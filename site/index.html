Optics · Field notes

Why a drop of water magnifies

A drop on a page is a small, thick lens. Light leaving the paper bends as it enters the water and again as it leaves, so the letters under the drop look larger.

Water bends light less than glass: its refractive index is about 1.33, against about 1.5 for window glass.

At the rim the surface is steepest. That is where the image stretches most.

    Skins by anyone

    What makes skin communities work

    Customization ecosystems thrive when a skin is a small, legible file anyone can make from images and a few values, previewed on the real UI before it is applied, credited to everyone who made or mixed it, and safe to try because missing pieces fall back and any change can be undone.

    A .webbyskin already copies osu!'s fixed-filename PNG + JSON model, so Webby can borrow what osu!, Winamp and Obsidian proved: render a real note at import time, show credits and validation next to the Install button, and make fallback and rollback invisible. Notes are personal, so the install moment has to reassure (no code, never touches note content) as much as it delights.

    • Preview on the real surface

      The skin is shown applied to the actual UI (playfield, player, client) before you commit, not as a swatch list.

      For Webby: The install sheet renders a live note (expanded, collapsed bar, decoration, palette chips) and a Library row with the incoming skin, with Light/Dark/High-contrast toggles and sound play buttons, before Install.

      Seen in: Winamp Skin Museum opening each skin live in Webamp; osuck skin.ini editor gameplay preview; Omarchy/Aether preview modal; Discord custom themes recoloring the client live

    • Fixed filenames make skins mixable

      Elements are addressed by well-known filenames, so people swap one PNG or merge two skins by copying files, and tools check files against the expected set.

      For Webby: Publish the canonical filename list, show '14 of 31 elements provided, rest from Default' on the install sheet, and add 'Use this element from...' in the Library skin detail to mix installed skins.

      Seen in: osu! skin folders (hitcircle@2x.png, cursor.png, applause.ogg) dropped into the osuck editor; osu!lazer skin editor sprite picker; 'Mixer' credits on osuck skin listings

    • Credits as metadata, with roles

      Authors travel with the skin and are shown wherever it appears, including roles such as creator and mixer, and forks name their source.

      For Webby: skin.json carries authors with roles, basedOn, version and license; the install sheet and Library show them; editing a copy adds the editor as Mixer and keeps the originals.

      Seen in: osuck listings (Creator / Mixer / Gameplay); Obsidian detail pages (author, downloads); mnml credited as a fork of kepano's Minimal

    • Few tokens in, full look out

      A tiny set of inputs (a few colors, fonts, contrast) is enough, and the app derives everything else.

      For Webby: A valid skin can be three colors in skin.json; Webby derives borders, hover, header and high-contrast values from them, and any omitted group falls back to Default so beginner skins still look finished.

      Seen in: Codex themes (accent, background, foreground, fonts, contrast); Discord (up to 5 colors); Ghostty generating 256 colors from a 16-color base

    • Presets and Import live together

      Installed themes appear as rendered thumbnails with Import (and Copy/Export) in the same picker.

      For Webby: The Appearance popover is a grid of mini-notes rendered from each installed skin, ending with 'Import Skin...'; each tile has Duplicate & Edit, Reveal in Finder and Export.

      Seen in: Xcode Presets popover with 'Import...' at the bottom; Codex 'Import' and 'Copy theme' next to the theme menu

    • Share as one file or one link

      A theme moves as a single file, a copyable string or a URL that opens the app's own install flow.

      For Webby: Export always produces one .webbyskin; an optional webby://skin link downloads, validates and opens the same install sheet; nothing applies without the sheet.

      Seen in: Winamp .wsz with [Download] [Share] links; Omarchy 'paste the URL' installer and aether://apply deep links; Codex 'Copy theme'

    • Trust signals at the install moment

      Automated checks, disclosures and a report path are shown before install.

      For Webby: The sheet shows a validation summary (files, size, 'images and sounds only, no code', re-encoded images, sound length) plus warnings tied to filenames; any future gallery gets a Report button.

      Seen in: Obsidian scorecards (scans of every version, 'Review Passed', disclosures); Winamp Skin Museum 'Report as NSFW'

    • Remix from anything

      Every theme can be opened in an editor, and remixes are a normal path rather than a hack.

      For Webby: 'Duplicate & Edit' copies the skin to a folder, records basedOn, opens it in Finder and pins a live preview note that hot-reloads as files change.

      Seen in: Aether 'Edit' beside 'Apply'; osuck editor importing .osk/.zip/folders; mnml forked from Minimal
    Proposed import flow

    From file to note in six steps

    The lab above runs steps 2 to 4 in your browser. Webby would add the Undo toast, Update and Keep both handling, and webby:// links.

    1. One path for every entry point: double-click a .webbyskin, drop it on the Library window (the window shows a 'Drop to preview skin' target), choose Import Skin... in the Appearance grid, or open a webby://skin link.
    2. Validate off the main thread in a temp folder: ZIP limits (size, file count, no path traversal or symlinks), allowlist of skin.json + PNG + WAV, decode and re-encode images, check pixel caps and 9-slice insets, check schema version; unknown keys are ignored and listed.
    3. Show the install sheet: a live note preview (expanded, collapsed, decoration) with Light/Dark/High-contrast toggles and sound play buttons; name, version, credits by role, and 'N of 31 elements, rest from Default'.
    4. List problems by filename: errors block install (corrupt PNG), warnings do not (no dark variant, so it falls back; low text contrast).
    5. Choose Install, or Install & Apply; if the same skin id exists, offer 'Update 1.1 to 1.2' or 'Keep both' and keep the old version for rollback.
    6. After applying, show an Undo toast that restores the previous skin; the skin appears in the Library with credits, Reveal in Finder, Duplicate & Edit and Export.

    Risks

    Safety: crafted ZIPs (bombs, path traversal, symlinks), malformed PNG/WAV aimed at decoders, huge images or long or loud sounds. Mitigate with a strict allowlist, size and pixel caps, decode in a limited helper and re-encode, clamp sound duration and volume, and no network fetches or fonts from inside skin.json. Name system fonts only, falling back when one is missing. Legal: fan skins routinely use copyrighted characters and art (Zelda Winamp skin, anime osu! skins). Local import is the user's choice, but any official gallery needs a license field, original or licensed art for featured skins, and a takedown and report path. Quality: low-contrast or busy skins can make note text unreadable. Run a contrast check in the sheet, let high-contrast overrides win when the system Increase Contrast setting is on, and fall back to default text colors below a threshold. Longevity: themes that hook internals break on every update, as Spicetify themes do after Spotify updates. Keep element names and the schema stable and versioned (minAppVersion), migrate old skins, and fall back per element so a broken skin never blanks a note. UX and trust: links or double-clicks must never silently re-skin the app. Always show the sheet, keep Undo, and make sure sharing or exporting a skin can never include note content or screenshots of real notes.

    Clear Glass · Principles

    Five rules for the glass

    Each rule comes from at least one reference below. The chips link to them. Together they keep the glossy look in check: glass where it helps you read, and nothing extra elsewhere.

    • Lens, not sheet

      A note bends the page under it instead of covering it, so you keep your place. Text sits on a frosted inner layer, which keeps it readable over any page.

      @HeyLabii@AndrewPrifer

    • One light, top left

      Every highlight on notes, buttons and the icon comes from the same source, at about 45° from the top left. A highlight that disagrees with the others looks like a sticker.

      @figma Light@1000kilobytes

    • Liquid only at the moments that matter

      Shapes morph on create, collapse and merge, and nowhere else. Typing, dragging, scrolling and menus respond instantly.

      @SwiftyAlex@shadcn

    • Readable before glossy

      Frost increases with the amount of text. Reduce Transparency and Increase Contrast switch the note to a solid surface. Every skin still has to pass the contrast floor.

      @flarup on Tahoe@Codelaby

    • Refraction should do a job

      Glass can reveal things as well as decorate. Proposed: hold ⌥ over a note to make it fully clear and read the page underneath.

      @ty_kra_lab@sentry_fka

    Clear Glass · Guardrails

    Do and don't

    Most glass interfaces fail because of readability. These guardrails keep that from happening.

    Do
    • Keep text on frost, and save visible refraction for the rim and the collapsed bar.
    • Light every highlight from the top left: notes, buttons, the voice orb and the icon.
    • Morph only on create, collapse and merge.
    • Switch to the solid surface when Reduce Transparency or Increase Contrast is on.
    • Let the tint pick up the page's color, then limit its saturation so notes don't look like ads.
    Don't
    • Put body text over refraction that hasn't been frosted.
    • Animate typing, dragging, scrolling or menus.
    • Stack glass on glass. A note's menu over a note needs more frost, or it becomes unreadable.
    • Add gloss to flat shapes. A highlight has to explain an edge.
    • Use rainbow dispersion on anything smaller than the note's own edge.
    Platform note

    Webby targets macOS 14 and later, but native Liquid Glass (glassEffect, GlassEffectContainer, NSGlassEffectView) needs macOS 26. On macOS 26 and later, notes would use system glass. That would reverse plan decision 21, which keeps Liquid Glass off note bodies because the HIG keeps it out of the content layer. On 14 and 15, they would fall back to the skin's NSVisualEffectView material with the drawn rim and sheen. Either way, the direction has to look right without true refraction.

    Open questions
    • Should surface.material get a glass value, with a defined fallback on macOS 14 and 15?
    • Should the light angle and rim fringe be skin tokens or fixed by the app, so every skin agrees with the system light?
    • Is Peek (hold ⌥ to clear a note) worth a global key, given notes are panels above Chrome?
    • How much tint pick-up is allowed before a note stops looking like Webby's?

    Materials

    Off-white cotton or laid paper with fine fibres and a very faint fold line. Pastel sticky-pad stock with slightly irregular edges. Translucent masking or washi tape with toothed torn ends. Kraft-brown tabs. Die-cut vinyl stickers with a white border of about 3 pt. Perforated postage-stamp edges. Ruled lines with a red margin. Riso halftone and misregistration go in decoration only, never behind text.

    Motion

    The skin format has no motion fields, so these are app-level suggestions. A new note settles with a 1–2° tilt and the shadow tightens over about 120 ms, like pressing it down. On drag the note lifts and the shadow lengthens. When a note is moved, a faint glue-residue ghost could stay briefly at its old anchor (see the DannPetty ref). Deleting could crumple the note instead of fading it (see the jhey crumple ref). Keep every effect under 250 ms and turn them off when Reduce Motion is on.

    Sound

    Quiet, short, dry, mono WAVs at 44.1 kHz, about −20 LUFS. note-create.wav: a short masking-tape tear followed by a palm press (about 220 ms). voice-start.wav: a soft rubber-stamp thunk (about 120 ms). voice-stop.wav: two pencil taps on paper (about 150 ms). No music, no reverb tails.

    Risks

    1. Grain and fibres under text lower legibility. Handwriting fonts slow reading and lack glyphs outside Latin, so keep them opt-in or limited to titles. 3. A tape or sticker decoration can cover the first line or the icons. Anchor it above the top edge and test on short, collapsed and narrow notes. 4. Twee scrapbook clutter: use one decoration per skin, a muted base palette, and save riso fluoro for accents, never as text colour. 5. Dark mode paper rarely convinces.     Direction · Built-in (v1.1)

    Graphite

    Notes as quiet instrument panels: tuned near-black greys, 1 pt hairlines, mono metadata and a single signal colour, so a note reads like a pro tool's inspector rather than a paper sticker.

    A note pinned over a busy web page or app has to be dense, legible and calm, and Graphite keeps it there. Small mono headers ('github.com/pulls · 3h ago') and keyboard legends suit people who live in Linear, Raycast and terminals, and those are the people most likely to leave notes on tools.

    Opaque, not glass: material 'none' on note surfaces so the page behind never smears into the text. Depth comes from three tuned greys (#0B0C0E, #16171A, #1D1E22), a 1 pt border at about 10% white, and a 1 px inner top highlight at about 5% white baked into the 9-slice. A 2–3% blue-noise grain is baked into the note-body centre and tiled, never stretched, so large notes stay crisp. The Library sidebar may use the 'sidebar' material, but keep it dim.

    Motion

    Small and exact. Show and hide take 120–160 ms ease-out (opacity plus a 4 pt translate, no scale bounce), and collapse or expand animates height over 140 ms. The focus ring appears instantly and fades out over 120 ms. Spinners step frame by frame at about 80 ms per frame, never easing. With Reduce Motion on, everything becomes an opacity cross-fade under 100 ms.

    Sound

    Nearly silent and mechanical. note-create: a 25–35 ms soft low-profile key click, dry with no reverb, peaking around -20 dBFS. voice-start: two short sine blips rising from 880 to 1320 Hz, 40 ms each with a 20 ms gap. voice-stop: the same blips falling. Nothing over 120 ms, nothing musical.

    A dark note on a white page can feel like a black hole, so ship the light Paper variant, follow system appearance, and keep the fill at #16171A rather than #000. Grey-on-grey can fail the contrast floor; body text must stay Bone (about 14:1), and Smoke (#8B8B93, about 5:1) is reserved for meta, never for note text.     Field Instrument

    Each note is a small, well-made device: a warm moulded housing, a recessed display window, printed labels, and one safety-orange signal light, with a mechanical click when something switches on.

    Sticky notes that come back to a page work like labels and indicator lights on a bench instrument, so a hardware skin makes each note feel like a physical tag clipped to that site. The collapsed one-line bar fits naturally as a small LCD readout.

    Palette

    Type

    Display Doto (Google Fonts, dot-matrix variable font). Use it only inside PNG art for header labels, collapsed-bar captions and decoration plates, because skins cannot bundle fonts.

    Body SF Pro Text (Apple system) at 14 pt regular, the most readable choice for note text. Alternatively SF Mono 13 pt for the full instrument look.

    Mono SF Mono (Apple system). If installed, Geist Mono or JetBrains Mono (Google Fonts) are close substitutes.

    Materials

    Matte injection-moulded ABS in warm white or graphite, with a 1 px top highlight, a 1 px lower shade and a faint 2 pt chamfer. Recessed display windows (dark glass or a backlit blue-grey LCD) carry an inner shadow. Labels are pad-printed or engraved; the only metal is brushed aluminium on small knob or plate details. Everything is opaque: no blur and no glass.

    Motion

    Mechanical and stepped rather than floaty. Presses sink 1-2 pt with the shadow collapsing (about 80 ms) and spring back in about 120 ms. Collapse and expand move like a shutter (about 150 ms ease-out, no bounce). LEDs blink at 1 Hz while voice is active. Dot-matrix orb frames step at 8-12 fps with hard cuts, not tweens. Skins only supply frames; Webby owns the timing.

    Sound

    Short, dry, quiet mechanical sounds (44.1 kHz/16-bit mono WAV, under 150 ms, peaks around -18 dBFS, soft exponential attack): note-create is a latching key 'clack', voice-start a toggle 'click' with a small rising 2-tone blip, voice-stop the toggle returning with a falling blip. Record or synthesise them; never sample branded devices.
